## SERVICE FOURNI
| Element | Description |
| :- | :- |
| Type de service | Agrégateur entièrement automatisé |
| Type de contenu | Articles scientifiques (articles de revues, actes de conférences, rapports techniques ou leurs ébauches, thèses, prépublications, postpublications ou résumés) |
| Langue du contenu | Pas de limitation |
| Provenance géographique du contenu | Pas de limitation |
| Niveau d'indexation des publications | Articles |
| Full text | Lien vers le texte intégral lorsqu'il est disponible |
| Sources de l'index | Tout site web contenant des articles scientifiques avec une URL correcte |
| Données collectées | Métadonnées relatives aux articles et/ou aux PDF, le cas échéant. |
| Standards supportés | Meta-tags HTML incluant :<br>metatags Highwire Press<br>metatags BE Press<br>metatags PRISM<br>metatags Dublin Core |
| Bibliodiversité | Aucune restriction quant à la langue du contenu ou au modèle économique de l'édition.<br>L'indexation repose sur le web-crawling automatique sans évaluation de la qualité (elle inclut également le contenu généré par l'IA).<br>Des règles de classement opaques confèrent une plus grande visibilité aux articles les plus cités, ce qui accroît le nombre de citations des articles en anglais. |
| Services additionnels | Indicateurs Google Scholar (visibilité et influence des articles récents dans les publications scientifiques) :<br>https://scholar.google.com/intl/fr/scholar/metrics.html <br><br>Profils Google Scholar (présentation des publications des auteurs) : https://scholar.google.com/intl/fr/scholar/citations.html  |

## PROCESSUS D'INCLUSION
| Element | Description |
| :- | :- |
| Options d'inclusion | Google Scholar utilise des logiciels automatisés, appelés « robots » ou « crawlers », pour extraire les fichiers et les inclure dans les résultats de recherche. Le site web de la revue doit être structuré de manière à permettre cette exploration. Les crawlers automatiques doivent pouvoir découvrir et extraire les URL de tous les articles, et mettre à jour régulièrement leur contenu à partir du site web de la revue. |
| Processus de collecte des données  | Web crawling |
| Formulaire pour les fournisseurs de données | néant |
| Informations de contact | néant |

## CONDITIONS MINIMALES
| Element | Description |
| :- | :- |
| Critères éditoriaux | néant |
| Formats de données | HTML ou PDF |
| Standards de métadonnées | Meta-tags HTML incluant :<br>metatags Highwire Press<br>metatags BE Press<br>metatags PRISM<br>metatags Dublin Core |
| Formats de métadonnées | néant |
| Métadonnées minimales | Pour les publications PDF :<br>Titre (en gros caractères)<br>Auteurs (sous le titre)<br>Référence bibliographique (en bas de page)<br>Bibliographie (section séparée)<br><br>Pour les publications HTML (métadonnées incluses dans les meta-tags du fichier HTML) :<br>Titre<br>Auteurs<br>Date de publication<br>Référence bibliographique<br>Bibliographie |

| Spécifications SEO/UX | Selon le nombre d'articles sur le site web :<br>- Si le nombre est faible : tous les articles doivent être listés sur une seule page.<br>- Si le nombre est élevé : le site web doit contenir la liste complète de tous les articles, classés par ordre de publication ou par date d'entrée.<br>- Si le nombre est supérieur à 100 000 : une interface de navigation spécifique avec les dernières mises à jour est requise.<br>- Si le fichier robots.txt est utilisé, il doit être configuré pour autoriser l'exploration du site par les robots de GScholar. |
